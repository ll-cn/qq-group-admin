# 官方群管（qq-group-admin）

QQ 官方机器人的群管插件，基于 QQ 机器人开放平台 v2 群接口（`restrict_chat_setting`、`batch_remove_members`、`member_blacklist`、`members`、`info`、`bot_state`），跑在 alemonjs 框架上。

禁言、解禁、全员禁言、踢人、拉黑、黑名单、成员列表、群信息、入群欢迎、退群通知，外加一层自动群管（刷屏 / 违禁词）。

## 一、先看这几条官方限制（不是插件的问题）

| 限制 | 说明 |
| --- | --- |
| **机器人必须是群管理员** | 禁言、全员禁言、踢人、拉黑全部要求机器人有群管理员身份；普通成员身份调用会被官方接口拒绝。插件会先查自己的身份（`bot_state`），不是管理员就直接提示，不会假装成功。 |
| **只能处置普通成员** | 群主、管理员、机器人本身都动不了。插件在处置后会回查一次禁言列表，状态没变会明确告诉你「对方可能是管理员或群主」。 |
| **撤回只能撤自己的消息** | 官方接口只允许机器人撤回**自己发的**消息。所以违禁词命中只能禁言，撤不掉别人的消息。 |
| **禁言最长 30 天、单次最多 10 人** | 插件已按 30 天夹紧，批量自动按 10 人分批。 |
| **@ 常常拿不到 openid** | 默认只推「@机器人」的消息，而且这时 `mentions` 里通常没有第三方。所以 `#禁言 @他` 常常解析不出目标，请改用 **openid** 或 **#序号**（见下）。 |
| **群成员列表需要白名单** | `GET /v2/groups/{group_openid}/members` 仅白名单机器人可用（报 `11253`）。没有权限时，昵称/序号就没法解析，只能用 openid 指定对象。 |

## 二、安装

```bash
# 假设机器人根目录是 alemon（有 alemon.config.yaml 的那层）
cd alemon
# 把 qq-group-admin 整个目录放到 packages/ 下
npm i ./packages/qq-group-admin
```

在 `alemon.config.yaml` 的 `apps` 里加一行（**不要用 `alemonc add apps`，会清空 apps**）：

```yaml
apps:
  alemonjs-cheese: true
  alemonjs-load-gscore: true
  alemonjs-load-yunzai: true
  qq-group-admin: true
```

放哪个位置都行。本插件注册的是**中间件**（`middlewareRouter`），中间件在 response 链之前执行，不受 apps 加载顺序影响。

这点很关键：如果改用 `responseRouter` 注册，而环境里装了 `alemonjs-load-yunzai`，它会注册一条 `regular: /.*/` 的兜底路由——把消息转发进云崽之后**不调用 `next()`**，整条链就停在那里，排在它后面的插件永远收不到消息。现象是：插件有加载横幅，但发指令只有云崽的 `[Group ...][#群管帮助]...` 日志，插件一行都没有。

本插件在每条消息处理完都会调用 `next()`，所以命令归插件、其他消息照常进云崽。

重启机器人。启动日志里出现 `[官方群管] v1.0.0 已加载` 就是好了。

首次启动会自动生成 `config/config.yaml`（随包已带一份默认的）。

## 三、指令

`#群管帮助` 默认渲染成一张图片（jsxp 的 `renderHtmlToBuffer` + Playwright 截图，828 宽 @2x）。渲染失败——没装 `jsxp`、找不到浏览器、截图报错——会自动退回纯文本，不会没有响应。

浏览器由 jsxp 自己探测（Chrome / Chromium / Edge 都会找）。部署机如果没有浏览器，可以指定：

```bash
export JSXP_EXECUTABLE_PATH=/usr/bin/google-chrome
```

前缀 `#`、`＃`、`/`、`!`、`！` 都行，也可以直接发不带前缀的（如 `群管帮助`）。

### 禁言

```
#禁言 @他 10m          禁言 10 分钟
#禁言 张三 1h           按昵称（需要群成员列表权限）
#禁言 #3 2d             按群成员列表里的第 3 位
#禁言 EC58D8... 600     直接给 openid
#解禁 张三              解除禁言
#禁言状态               当前被禁言的人 + 全员禁言状态
#全员禁言               开启全员禁言
#解除全员禁言           关闭全员禁言
```

时长写法：`600`（秒）、`600s`、`10m`、`1h`、`2d`、`10分钟`、`1天`，不写就用配置里的默认值（10 分钟）。

### 成员

```
#踢人 张三              移出群
#拉黑 张三              移出并拉黑
#解除拉黑 张三          解除拉黑
#黑名单                 黑名单列表
#群成员                 成员编号
#群成员 openid          带上完整 openid（配置 admins 时用）
#刷新成员               清空成员缓存
```

### 其他

```
#群信息                 群名、人数、我的身份、全员禁言状态、自动群管状态、累计处置数
#撤回                   撤回我自己上一条消息
#群管面板               按钮面板，点一下直接执行
#入群申请               待审批列表（机器人需是群管理员）
#通过 2 / #拒绝 2 理由   按列表序号审批
#自动审批               查看/开关本群的自动审批策略
```

### 入群申请

机器人是群管理员时，官方会推 `GROUP_JOIN_REQUEST` 事件，插件往群里发一条通知：

```
有人申请加群：小王
验证消息：朋友介绍
[通过] [拒绝]
```

按钮是回调类型，`data` 里直接带 `join_request_id` 和申请人 openid（`join_ok:<申请ID>:<openid>`），点一下就走审批接口，不依赖列表缓存。

通知字段：昵称、验证消息、问答、来源（主动申请 / 被邀请 + 邀请人）、风险提示、是否机器人账号。

`#入群申请` 的列表也带按钮，每个申请人一行「通过 N / 拒绝 N」（超过 5 人时按钮只覆盖前 5 位，其余用指令）。

#### 自定义通知文案

`config/config.yaml` 里的 `joinRequest.template` 就是通知正文，一行一项，随便增删、调顺序、改措辞：

```yaml
joinRequest:
  notify: true
  buttons: true
  template:
    - "**有新成员申请加群**"
    - ""
    - "昵称：{name}"
    - "验证消息：{verify}"
    - "{qa}"
    - "来源：{source}"
    - "风险：{risk}"
    - "{bot}"
```

可用变量：

| 变量 | 内容 |
| --- | --- |
| `{name}` | 申请人昵称 |
| `{verify}` | 验证消息 |
| `{qa}` | 问题 / 答案（最多 3 组，多行） |
| `{source}` | 主动申请 / 被邀请（附邀请人） |
| `{risk}` | 风险提示 |
| `{bot}` | 机器人账号提示 |

三条规则：

- 一行里用到的变量**全为空**时，这一行不显示（没填验证消息就不会留个空标签）
- 空字符串行保留成空行，用来分段
- **以 `*` 开头的行必须加引号**，否则 YAML 会把它当别名，配置直接解析失败

也可以把 `template` 写成一段多行字符串，按换行拆分。改完保存即时生效，不用重启。

从旧版本升级、配置文件里还没有 `template` 时，插件启动会自动把带注释的这一段补进 `config/config.yaml`（只补一次，不动你已有的其他配置），打开文件就能照着改。

也可以用指令：

```
#入群申请          拉待审批列表（默认 10 条，可写成 #入群申请 20）
#通过 2            通过第 2 条
#拒绝 2 资料不全    拒绝并附理由
#自动审批          查看本群策略
#自动审批 开/关    切换（平台级策略，绑定本群 openid）
```

几个限制：

- **机器人不是群管理员就收不到这个事件**，这是官方的前置条件，不是插件问题。
- 序号来自「上一次 `#入群申请` 拉到的列表」。审批完该条会从缓存移除，序号会变，重新拉一次再操作。
- `#自动审批` 是平台侧的「自动通过」策略开关，只控制开关，不含关键词/问答匹配（那些在开放平台后台配）。

### 入群欢迎 / 退群通知

官方会推 `GROUP_MEMBER_ADD` / `GROUP_MEMBER_REMOVE`（这条不需要管理员身份），插件可以自动发欢迎和退群提示。两个都默认关闭：

```yaml
welcome:
  enabled: true
  # 是否 @ 新成员（走 markdown 消息）
  mention: true
  text: "欢迎 {user} 加入本群，先看看群公告哦～"

leave:
  enabled: true
  text: "{user} 退出了群聊"
```

`{user}` 替换成昵称。`mention: true` 时用 markdown 消息，`<qqbot-at-user>` @ 的对方 openid；机器人没有 markdown 权限会退回纯文本（只是不 @ 了）。

官方事件里没有退群原因，所以「主动退群」和「被移出」区分不出来，文案得写通用的。

**打开即接管**：中间件跑在 response 链之前，插件把消息发出去之后就不再调用 `next()`，事件到此为止——云崽自带的 `进群退群通知.js` 收不到，不会同一个人收到两条欢迎。配置关着（默认）则完全放行，仍由云崽那边处理。发失败时也会放行，宁可重复一条也不让提示丢掉。

**昵称来源**：官方 `GROUP_MEMBER_ADD` / `GROUP_MEMBER_REMOVE` 的推送里**没有昵称**，只有 openid。插件按三个来源补昵称，按顺序兜底：

1. 事件里带的 `UserName`（有些通道会给）
2. 本地昵称库 `data/nickname.json`——平时拉群成员列表（`#群成员` 指令、入群触发）时会把**全群**成员的昵称记下来，最多 3000 条
3. 实时拉一次成员列表查（入群时强制刷新，因为旧名单里肯定没有新人）

查不到才显示「某位群友」/「新成员」。注意第 2、3 条依赖**群成员列表接口的白名单权限**（报 11253 就是没权限），有权限的话进退群基本都能显示真名。

### 按钮面板

`#群管面板` 发出一条带按钮的消息：禁言状态 / 群成员 / 全员禁言 / 解除全员禁言 / 群信息 / 群管帮助。

改这块代码前先看这几条，都是踩过的：

- 群聊只能用**回调按钮**（`action.type = 1`）。框架默认是 `command`（type 2），群聊里点了没有反应，必须显式 `addButton(标题, data, { type: 'call' })`。指令按钮（`enter: true`）只在单聊可用。
- **带按钮的消息必须同时带 markdown 内容**。qq-bot 遇到 `keyboard` 会走 `msg_type: 2`（markdown 消息），如果只有纯文本没有 markdown，官方直接拒掉——现象就是「执行了但群里没反应」。所以面板/申请通知的文字都用 `Format.createMarkdown()` 承载。
- 机器人没有 markdown 权限时同样会发失败，插件会自动补发一条纯文本并在末尾提示改用指令，不会静默。
- 按钮 `data` 就是点击后回传的 `button_data`，**不能含空格**。框架对不含空格的 interaction 文本不走命令解析（整串当 key，也不剥 `#` 前缀），所以按钮由一条独立的 `interaction.create` 路由 `onButton` 分发，不复用命令路由。
- 框架会把 `router.res` 的 `selects` 展开成全部事件，因此 `guard` / `welcome` 必须自己按 `event.name` 过滤，否则点一次按钮会被当成一条聊天消息算进刷屏。
- 按钮回调的被动回复用 `event_id`（不是 `msg_id`），框架 `sends` 已处理；`autoInteractionAck` 默认开启，不用手写应答。

### 自动群管

```
#群管开关               查看状态
#群管开关 开            开启本群自动群管
#群管开关 关            关闭
#违禁词                 查看
#违禁词 添加 引流        添加
#违禁词 删除 引流        删除
#违禁词 清空             清空
#刷屏设置 10 8 600      10 秒内 8 条 → 禁言 600 秒
#刷屏设置               查看当前规则
```

自动群管对**每条机器人能收到的消息**生效。默认模式下群里不 @ 机器人是收不到消息的，想让刷屏检测真正管用，需要在手机 QQ 的群里给机器人开「获取群内全部消息」。

命中违禁词 / 刷屏后，同一人 60 秒内不会被重复处置；管理员和群主不会被自动处置。

## 四、配置

**推荐直接在网页里改**：浏览器打开

```
http://<机器人地址>:<serverPort>/apps/qq-group-admin/
```

`serverPort` 就是 `alemon.config.yaml` 里的那个（默认 18110）。页面上可以改所有配置，保存即时生效，不用重启；注释也不会被冲掉。面板默认没有口令——它和 alemon 的接口一样暴露在 `serverPort` 端口上，机器人不在本机时建议在面板最后一栏设个 `web.token`。

也可以手改 `config/config.yaml`（改完保存即生效，每次指令都会检查文件变动）：

```yaml
admins: []                 # 额外管理员 openid（机器人主人始终可用）
defaultMuteSeconds: 600    # 默认禁言时长
maxMuteSeconds: 2592000    # 单次上限（30 天，别调大）
verifyAfterMute: true      # 处置后回查，确认真的生效
memberCacheSeconds: 600    # 成员列表缓存
memberMaxPages: 4          # 成员列表最多翻几页（每页 30）
auto:                      # 自动群管的各群初始默认值
  enabled: false
  floodSeconds: 10
  floodCount: 8
  floodMuteSeconds: 600
  bannedMuteSeconds: 600
  words: []
welcome:                   # 入群欢迎
  enabled: false
  text: "欢迎 {user} 加入本群，先看看群公告哦～"
```

群级数据（每群的开关、违禁词、统计）落在 `data/groups/<group_openid>.json`，删掉就回到默认值。

## 五、权限是怎么判的

按顺序，命中任意一条就能用：

1. 机器人主人（`IsMaster`）
2. `config/config.yaml` 的 `admins` 里
3. 该群 `data/groups/*.json` 的 `admins` 里
4. 事件里带 `author.member_role` 且是 `admin` / `owner`（只有全量消息模式下才有这个字段）

官方接口**没有**「查群管理员名单」的能力，所以第 4 条不保证生效。稳妥的做法是把自己的 openid 加进 `admins`：在群里发 `#群成员 openid` 拿到即可。

## 六、排错

| 现象 | 原因 |
| --- | --- |
| 提示「我还没被设成群管理员」 | 去群设置里把机器人设为管理员 |
| `11253` / 「拉不到群成员列表」 | 群成员列表要白名单权限，向平台运营申请；或用 openid 指定对象 |
| 提示成功但对方还能说话 | 看回复里的「生效校验」那行：状态没变说明对方是管理员/群主，官方不允许处置 |
| 群里发指令没反应 | 官方默认只推「@机器人」的消息，记得 @ 一下；或给机器人开「获取群内全部消息」 |
| 日志里有加载横幅，但发指令毫无反应 | 本插件走中间件不会遇到；如果自己改回 `responseRouter`，会被 `alemonjs-load-yunzai` 的 `/.*​/` 兜底路由吞掉 |
| 自动群管不生效 | `#群管开关` 看是不是关的；再看上面那条消息范围设置 |
| 昵称解析不出人 | 成员列表没权限，或昵称有重名（会提示改用 #序号 / openid） |
| 点按钮没反应 | 群聊只认回调按钮，框架默认给的是 `command`（指令按钮），代码里已显式指定 `call`；自己加按钮时别忘了 |
| 一个人进群收到两条欢迎 | 插件和云崽的 `进群退群通知.js` 同时开了。插件开着会自动接管，正常不会重复；若仍在重复，说明插件那条没发出去（看日志「没发出去，事件交回后续处理」） |
| 网页面板打不开（404） | 端口用错。面板在 `serverPort`（默认 18110）上，不是 `port`/`server.port`（那是 CBP/WebSocket，17117） |
| 面板要口令 | `config/config.yaml` 的 `web.token` 设了值。URL 加 `?token=xxx` 进入，或清空 token 恢复开放 |
| 退群显示「某位群友」 | 官方事件不带昵称，该成员从没在群里发过言，插件没记到名字 |
| 云崽那份 `进群退群通知` 里的 `notice.group.member.increase` 不生效 | 桥接只把成员事件发成 `notice.group_increase` / `notice.group_decrease`，`notice.group.member.*` 永远不会触发，那几个类可以直接删 |
